# Fog of War и видимость карты

Fog of War — базовый VTT-слой LoreForge для контроля того, какую часть сцены видит игрок.

## Модель

- `Scene` остаётся игровой картой внутри локации.
- `scene_visibility_layer` хранит общие слои сцены: полный туман, открытые области и заблокированные зоны.
- `player_scene_visibility` хранит персонально открытые области карты для участника кампании.

GM видит всю карту и все служебные слои. Player получает только свои открытые области. Viewer не получает GM-слои и видит только публичную видимость.

## API

- `GET /api/campaigns/:campaignId/scenes/:sceneId/visibility` — возвращает доступную видимость сцены для текущего пользователя.
- `POST /api/campaigns/:campaignId/scenes/:sceneId/reveal` — GM открывает область конкретному игроку.
- `POST /api/campaigns/:campaignId/scenes/:sceneId/reveal-all` — GM открывает всю карту конкретному игроку.
- `POST /api/campaigns/:campaignId/scenes/:sceneId/hide-area` — GM скрывает область.

Пример открытия области:

```powershell
curl -b work\cookies.txt -X POST http://localhost:3001/api/campaigns/1/scenes/1/reveal `
  -H "Content-Type: application/json" `
  -d '{"userId":4,"area":{"type":"rect","x":18,"y":18,"width":34,"height":34}}'
```

## Realtime

После изменения видимости backend отправляет событие:

```text
vision.updated
```

Событие получают:

- GM, потому что видит все изменения;
- только целевой игрок, если обновление персональное.

Другие игроки и viewer не получают чужие персональные данные видимости.

## Play Room

Порядок слоёв в центре Play Room:

1. изображение сцены;
2. Fog Layer;
3. открытые области;
4. токены карты;
5. подписи и GM-инструменты.

GM видит компактную панель **Туман войны**:

- выбрать игрока;
- открыть область;
- открыть всю карту;
- скрыть область.

Сейчас области задаются простыми прямоугольниками. Рисование произвольных полигонов мышью оставлено на следующий этап.

## Ограничения

- нет динамического света;
- нет теней и line of sight;
- нет pathfinding;
- нет fog-of-war history UI;
- нет сложного редактора масок.

Этот слой нужен как фундамент: backend-модель, правила доступа, REST API, realtime событие и первый UI-контроль для ГМа.
